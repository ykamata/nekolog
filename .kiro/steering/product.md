# 飼い猫の健康管理アプリ要件

## 機能

### 1. 食事管理機能の要件

- 飼い猫には 1 日に何度か餌を与えるため、以下の情報を記録する必要がある：
  - 餌を与えた時間
  - 餌の種類
  - 餌の量（グラム）
  - 餌のカロリー
- 飼い猫は 2 匹いるため、それぞれの猫の食事を管理する必要がある。
- 餌の種類はフード管理として登録し、入力時は選択式にする。
- 餌の量はグラムとカロリーのどちらでも入力できるようにする。
- 餌の登録は簡単に行えるように、数量もテキスト入力ではなく選択式にする。
  - 飼い猫の食事内容や量を記録・管理する機能。
- データは DB で管理する。

### 2. 薬管理機能の要件

- 飼い猫が服用する薬の管理機能。
- 与えているサプリメントの管理。
  - 処方内容の記録：
    - 薬の種類
    - 投与時間
    - 個数
- カレンダー形式の UI で投与記録を更新、確認する機能。
  - 1 日に複数回（朝・夜や、朝・昼・夜など）投与記録を付けられる機能が必要。
  - 誤って入力した記録は修正、あるいは削除できる必要がある。
- リマインダー機能：薬の投与時期を通知する。
- 消し込み機能：投与した薬に、投与済のステータスを設定
- データは DB で管理する。

### 3. 通院履歴の要件

- 飼い猫の通院履歴を記録する機能。
- 診察を受けた日時、病院、先生、処方内容、支払い金額を記録
- 入力は、プルダウン形式で、登録済みの選択肢にない内容を入力した時は記録し、次から選択できるようにする。
- カレンダー形式で、通院した日にマーク
- クリックすることでメモを登録・更新・確認
- データは DB で管理する。

### 4. 排泄管理の要件

- おしっこ、うんちの時間記録
- メモの添付
- カレンダー形式で表示、メモがある日は強調表示
- 個体別に管理
- データは DB で管理する。

### 5. フード管理の要件

- 飼い猫のフードの種類を管理するマスタメンテ機能。
- ドライフード、ウェットフードの区分が必要
- メーカー、商品名、購入時の単価、グラムあたりのカロリーを管理
- 登録 UI は、プルダウン形式で、登録済みの選択肢にない内容を入力した時は記録し、次から選択できるようにする。
- データは DB で管理する。

### 6. データ可視化の要件

- 健康状態や食事の履歴をグラフなどで表示する機能。
- ご飯、1 回あたりの食事内容、食事量の変移
  - ドライ、ウェット別の表示
- 1 日の合計カロリーの表示
  - ドライ、ウェット別の表示
- ご飯のデータは、LineChart で描画する
- モード切り替えで、ドライ、ウェット別の積み上げのバーチャートでも表示したい。

## アプリ要件

- PC とスマホで利用する
  - PC は Mac
  - スマホは iOS
- プライベートネットワーク内で運用する
- データは DB に登録する、MySQL を想定
- 1 ヶ月程度のデータを local storage に保管して、ネットワーク外でも参照したい

## ユーザー要件

- 飼い猫の健康管理アプリを使用するユーザーは、飼い主を想定している。
- ユーザーはプライベートネットワーク内で利用する。
- ユーザーは、iPhone, Mac を利用する。
- ブラウザは、iPhone は Safari, Chrome の最新 3 version をターゲットとする。Mac も同様。

## セキュリティ要件

- ユーザーデータは暗号化され、個人情報はプライバシーポリシーにしたがって管理されること。

## パフォーマンス要件

- アプリは、ユーザーの操作に対して 1 秒以内にレスポンスを返すこと。

## 障害復旧要件

- データは定期的にバックアップされ、障害発生時に 3 時間以内に復旧できる体制を整えること。

## ユーザビリティ要件

- アプリはシンプルなナビゲーションを持ち、ユーザーが直感的に操作できること。

## テスト要件

- 各機能はリリース前にテストされ、テストケースは文書化されること。

## API 要件

- フロントエンドとバックエンド間の通信は、REST API を使用して行うこと。

## デプロイ要件

- アプリはプライベートネットワーク内に常駐する Ubuntu サーバー上にデプロイする。
- アプリは Docker コンテナーとしてデプロイする。
- GitHub Actions から self hosted runner で CI/CD を組みたい。

## アクセシビリティ要件

- アプリが準拠すべきガイドライン、達成基準はとくに定めない。

## レスポンシブデザイン要件

- アプリは、スマホと PC の両方で快適に利用できるようにレスポンシブデザインを採用すること。

## モニタリング要件

- アプリのパフォーマンスとエラーログは、現場での問題を把握するためにモニタリングすること。
