# Requirements Document

## Introduction

このドキュメントでは、飼い猫の健康管理アプリにおける食事管理機能の要件を定義します。この機能は、飼い主が複数の猫の食事を記録・管理し、健康状態を把握するためのものです。Nuxt 3 と TypeScript を使用して実装され、データは Prisma を通じて MySQL（本番）または SQLite（開発）に保存されます。アプリはプライベートネットワーク内で運用され、PC（Mac）とスマートフォン（iOS）の両方で利用可能です。

## Requirements

### Requirement 1: 食事記録の登録

**User Story:** 飼い主として、猫の食事内容を記録したいので、餌の種類、量、与えた時間を簡単に入力できる機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主が食事記録画面を開く THEN システムは新しい食事記録を作成するためのフォームを表示する
2. WHEN 飼い主が猫を選択する THEN システムは登録されている猫のリストをプルダウンで表示する
3. WHEN 飼い主が餌の種類を選択する THEN システムは登録されているフードのリストをプルダウンで表示する
4. WHEN 飼い主が餌の量を入力する THEN システムはグラム単位（少数点以下１位まで）で数値を入力できるようにする
5. WHEN 飼い主が餌の量を入力する THEN システムはカロリー単位での入力も受け付けられるようにする
6. WHEN 飼い主が餌の量を入力する THEN システムは自動的にカロリー計算を行い表示する
7. WHEN 飼い主が食事時間を入力する THEN システムは日時選択 UI を提供する
8. WHEN 飼い主が食事記録を保存する THEN システムはデータベースに記録を保存し、成功メッセージを表示する
9. WHEN 飼い主が餌の量を選択式で入力する THEN システムは事前定義された量の選択肢を提供する
10. IF 入力内容に不備がある THEN システムはエラーメッセージを表示し、修正を促す

### Requirement 2: 食事記録の閲覧

**User Story:** 飼い主として、猫の食事履歴を確認したいので、過去の食事記録を一覧で見られる機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主が食事履歴画面を開く THEN システムは猫ごとの食事記録を時系列で表示する
2. WHEN 飼い主が特定の猫を選択する THEN システムはその猫の食事記録のみをフィルタリングして表示する
3. WHEN 飼い主が日付範囲を指定する THEN システムは指定された期間内の食事記録のみを表示する
4. WHEN 飼い主が食事記録の詳細を確認する THEN システムは選択された記録の詳細情報を表示する
5. WHEN 飼い主が食事記録を編集する THEN システムは編集フォームを表示し、データの更新を可能にする
6. WHEN 飼い主が食事記録を削除する THEN システムは確認ダイアログを表示し、承認後に記録を削除する

### Requirement 3: 猫の管理

**User Story:** 飼い主として、複数の猫を管理したいので、猫の情報を登録・編集できる機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主が猫管理画面を開く THEN システムは登録されている猫のリストを表示する
2. WHEN 飼い主が新しい猫を追加する THEN システムは猫の情報（名前、誕生日、体重など）を入力するフォームを表示する
3. WHEN 飼い主が猫の情報を保存する THEN システムはデータベースに情報を保存し、リストに反映する
4. WHEN 飼い主が猫の情報を編集する THEN システムは既存の情報を編集フォームに表示し、更新を可能にする
5. WHEN 飼い主が猫を削除する THEN システムは確認ダイアログを表示し、承認後に猫の情報を削除する
6. IF 削除対象の猫に関連する食事記録がある THEN システムは関連データの扱いについて選択肢を提供する

### Requirement 4: フード管理

**User Story:** 飼い主として、猫のフード情報を管理したいので、フードの種類や栄養情報を登録・編集できる機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主がフード管理画面を開く THEN システムは登録されているフードのリストを表示する
2. WHEN 飼い主が新しいフードを追加する THEN システムはフードの情報（名前、種類、カロリー/g、価格など）を入力するフォームを表示する
3. WHEN 飼い主がフードの種類を選択する THEN システムはドライフードとウェットフードの選択肢を提供する
4. WHEN 飼い主がフードの情報を保存する THEN システムはデータベースに情報を保存し、リストに反映する
5. WHEN 飼い主がフード情報を編集する THEN システムは既存の情報を編集フォームに表示し、更新を可能にする
6. WHEN 飼い主がフードを削除する THEN システムは確認ダイアログを表示し、承認後にフード情報を削除する
7. IF 削除対象のフードに関連する食事記録がある THEN システムは関連データの扱いについて選択肢を提供する

### Requirement 5: データ可視化

**User Story:** 飼い主として、猫の食事傾向を把握したいので、食事データをグラフで視覚化する機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主がデータ可視化画面を開く THEN システムは猫ごとの食事データをグラフで表示する
2. WHEN 飼い主が特定の猫を選択する THEN システムはその猫のデータのみを表示する
3. WHEN 飼い主が日付範囲を指定する THEN システムは指定された期間のデータを表示する
4. WHEN 飼い主がグラフタイプを選択する THEN システムは線グラフまたは棒グラフでデータを表示する
5. WHEN 飼い主がフードタイプでフィルタリングする THEN システムはドライフードとウェットフードを区別して表示する
6. WHEN 飼い主が 1 日の合計カロリーを確認する THEN システムは日ごとの合計カロリーを表示する

### Requirement 6: オフライン対応

**User Story:** 飼い主として、ネットワーク外でもアプリを使用したいので、一定期間のデータをローカルに保存する機能が欲しい。

#### Acceptance Criteria

1. WHEN アプリがオンライン状態で使用される THEN システムは最新の 1 ヶ月分のデータをローカルストレージに保存する
2. WHEN アプリがオフライン状態で起動される THEN システムはローカルに保存されたデータを使用して機能を提供する
3. WHEN アプリがオフライン状態で新しいデータが入力される THEN システムはローカルにデータを保存し、オンラインに復帰した際に同期する
4. WHEN アプリがオンラインに復帰する THEN システムはローカルに保存された未同期データをサーバーと同期する
5. IF オフライン中に編集されたデータとサーバー上のデータに競合がある THEN システムは競合解決のためのインターフェースを提供する

### Requirement 7: レスポンシブデザイン対応

**User Story:** 飼い主として、PC（Mac）とスマートフォン（iOS）の両方で快適に利用したいので、デバイスに応じて最適化された UI が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主が PC でアプリにアクセスする THEN システムは PC 向けのレイアウトで UI を表示する
2. WHEN 飼い主がスマートフォンでアプリにアクセスする THEN システムはモバイル向けのレイアウトで UI を表示する
3. WHEN 飼い主がタッチデバイスを使用する THEN システムはタッチ操作に適したボタンサイズとインタラクションを提供する
4. WHEN 飼い主が異なる画面サイズでアプリを使用する THEN システムは画面サイズに応じてレイアウトを調整する

### Requirement 8: パフォーマンス要件

**User Story:** 飼い主として、ストレスなくアプリを使用したいので、操作に対して迅速にレスポンスが返る機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主がアプリの任意の機能を操作する THEN システムは 1 秒以内にレスポンスを返す
2. WHEN 飼い主がデータの読み込みを行う THEN システムは適切なローディング表示を提供する
3. WHEN 飼い主が大量のデータを表示する THEN システムはページネーションまたは仮想スクロールを使用してパフォーマンスを維持する

### Requirement 9: セキュリティ要件

**User Story:** 飼い主として、猫の健康データを安全に管理したいので、データが適切に保護される機能が欲しい。

#### Acceptance Criteria

1. WHEN 飼い主がアプリにアクセスする THEN システムは JWT + Cookie ベースの認証を要求する
2. WHEN 飼い主のデータがデータベースに保存される THEN システムは適切な暗号化を行う
3. WHEN 飼い主がプライベートネットワーク外からアクセスを試みる THEN システムはアクセスを拒否する
4. WHEN 飼い主がセッションを終了する THEN システムは認証情報を適切にクリアする
