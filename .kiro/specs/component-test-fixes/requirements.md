# コンポーネントテスト修正要件

## 概要

`tests/components/*`で発生している215件のテストエラーを解消し、すべてのコンポーネントテストが正常に動作するようにする。主な問題は、DOMWrapper関連のエラー、コンポーネント要素の不存在、バリデーション機能の不備、レスポンシブ対応の不備、composableの未定義などである。

## 要件

### 要件1: DOMWrapper関連エラーの解消

**ユーザーストーリー:** 開発者として、テストでコンポーネントの要素を正しく取得・操作できるようにしたい。

#### 受け入れ基準

1. WHEN テストでコンポーネント要素を検索する THEN 要素が正しく見つかること
2. WHEN 要素に対してtrigger、setValue、attributesなどの操作を行う THEN エラーが発生しないこと
3. WHEN カスタムコンポーネント（DateTimePicker、VeterinaryMasterSelectorなど）をテストする THEN 適切なセレクタで要素を取得できること

### 要件2: コンポーネント要素の存在確認

**ユーザーストーリー:** 開発者として、テストで期待している要素がコンポーネントに実際に存在することを確認したい。

#### 受け入れ基準

1. WHEN テストでdata-testid属性を使用して要素を検索する THEN 対応する要素がコンポーネントに存在すること
2. WHEN フォームのバリデーションエラーが発生する THEN エラーメッセージ要素が表示されること
3. WHEN コンポーネントの状態が変化する THEN 対応するUI要素が適切に表示・非表示されること

### 要件3: バリデーション機能の実装

**ユーザーストーリー:** ユーザーとして、フォーム入力時に適切なバリデーションが動作し、エラーメッセージが表示されることを期待する。

#### 受け入れ基準

1. WHEN 必須項目が未入力の状態でフォーム送信を試行する THEN 適切なエラーメッセージが表示されること
2. WHEN 入力値が制限を超える（文字数制限など） THEN バリデーションエラーが表示されること
3. WHEN バリデーションエラーが発生する THEN エラーメッセージ要素にdata-testid属性が設定されていること

### 要件4: レスポンシブ対応の実装

**ユーザーストーリー:** ユーザーとして、モバイルやタブレットでアプリを使用する際に適切なレイアウトで表示されることを期待する。

#### 受け入れ基準

1. WHEN 画面サイズがモバイルサイズの場合 THEN コンポーネントに`mobile-layout`クラスが適用されること
2. WHEN 画面サイズがタブレットサイズの場合 THEN コンポーネントに`tablet-layout`クラスが適用されること
3. WHEN レスポンシブ対応が必要なコンポーネント THEN 適切なCSSクラスとスタイルが適用されること

### 要件5: Composableの実装と修正

**ユーザーストーリー:** 開発者として、コンポーネントで使用するcomposableが正しく定義され、テストで利用できるようにしたい。

#### 受け入れ基準

1. WHEN `useVeterinaryMasters`composableを使用する THEN 正しく定義され、必要な関数が提供されること
2. WHEN テストでcomposableをモックする THEN 適切にモック化され、テストが実行できること
3. WHEN composableの関数を呼び出す THEN 期待される動作が実行されること

### 要件6: カスタムコンポーネントのテスト対応

**ユーザーストーリー:** 開発者として、カスタムコンポーネント（DateTimePicker、VeterinaryMasterSelectorなど）を適切にテストできるようにしたい。

#### 受け入れ基準

1. WHEN DateTimePickerコンポーネントをテストする THEN setValue操作が正しく動作すること
2. WHEN VeterinaryMasterSelectorコンポーネントをテストする THEN 選択操作が正しく動作すること
3. WHEN カスタムコンポーネントの値を変更する THEN 親コンポーネントに適切にイベントが伝播されること

### 要件7: アクセシビリティ属性の実装

**ユーザーストーリー:** ユーザーとして、スクリーンリーダーなどの支援技術を使用してアプリを利用できるようにしたい。

#### 受け入れ基準

1. WHEN フォーム要素にエラーが発生する THEN aria-describedby属性でエラーメッセージと関連付けられること
2. WHEN カレンダーの日付セルを表示する THEN 適切なaria属性（aria-label、aria-describedbyなど）が設定されること
3. WHEN インタラクティブな要素を表示する THEN キーボードナビゲーションが適切に動作すること

### 要件8: データ表示の修正

**ユーザーストーリー:** ユーザーとして、通院記録や処方内容などのデータが正しく表示されることを期待する。

#### 受け入れ基準

1. WHEN 通院記録の処方内容を表示する THEN "Unknown Treatment"ではなく実際の処方内容名が表示されること
2. WHEN 複数の処方内容がある場合 THEN すべての処方内容が正しく表示されること
3. WHEN データが存在しない場合 THEN 適切な「データなし」メッセージが表示されること

### 要件9: フォーム送信状態の管理

**ユーザーストーリー:** ユーザーとして、フォーム送信中の状態が適切に表示され、重複送信が防止されることを期待する。

#### 受け入れ基準

1. WHEN フォーム送信中の場合 THEN 送信ボタンが無効化されること
2. WHEN フォーム送信中の場合 THEN ボタンのテキストが「保存中」などの適切な表示に変更されること
3. WHEN フォーム送信エラーが発生する THEN 適切なエラーメッセージが表示され、リトライ機能が提供されること

### 要件10: イベント処理の実装

**ユーザーストーリー:** 開発者として、コンポーネント間のイベント通信が正しく動作することを確認したい。

#### 受け入れ基準

1. WHEN ユーザーがボタンをクリックする THEN 適切なイベントが発火されること
2. WHEN フィルター条件を変更する THEN フィルター変更イベントが正しく発火されること
3. WHEN モーダルを開閉する THEN 開閉イベントが適切に処理されること
